# Plan 02-01: Multi-Site Profiles & Exponential Backoff Retries

## Objective

Deliver robust multi-site targeting and error resilience for WordPress batch expansions, ensuring the Katteb toolkit handles diverse fleet properties and recovers automatically from transient API/network drops.

## Tasks

<task type="auto">
  <name>Task 1: Implement Multi-Site Fleet Profile Registry and Validation</name>
  <files>src/katteb/wordpress.py</files>
  <action>
    Add a fleet site profile registry and validation helper `validate_site_alias(site: str) -> str` in `src/katteb/wordpress.py`.
    - Define known fleet site profiles (`destinations-ai`, `viatravelers`, `santorinisecrets`, `amsterdamlocalgems`, `parkervillas`, `realjourneytravels`, `everythingaboutgermany`, etc.).
    - Allow arbitrary custom WP-CLI aliases (e.g. `mysite.prod`) after validating that the alias string does not contain shell injection characters.
    - Add preflight alias verification method `check_site_connectivity(site: str) -> bool` in `WordPressFleetManager`.
  </action>
  <verify>
    Verify that calling `validate_site_alias("destinations-ai")` succeeds and malicious or malformed aliases raise a `ValueError`.
  </verify>
</task>

<task type="auto">
  <name>Task 2: Implement Exponential Backoff and Retry Policy for Katteb Client</name>
  <files>src/katteb/client.py, src/katteb/queue.py</files>
  <action>
    Implement a resilient retry mechanism with exponential backoff and jitter in `KattebClient` and `KattebQueueManager`:
    - Add retry parameters to `KattebClient._request()` for transient status codes (500, 502, 503, 504) and `requests.exceptions.RequestException` connection errors.
    - Default policy: 3 retry attempts, exponential factor of 2.0 (e.g. 2s, 4s, 8s delay), with random jitter.
    - Ensure 401 (auth) and 429 (rate-limit / concurrency lockout handled by queue) are NOT retried blindly by the generic 5xx retry loop.
    - In `KattebQueueManager`, wrap job status polling with this retry handler to prevent transient network drops from failing long-running generation jobs.
  </action>
  <verify>
    Verify with unit tests that simulated 502/503 responses trigger expected retry attempts before succeeding or raising `KattebAPIError`.
  </verify>
</task>
