# Plan 03-01: Activepieces Gateway Integration & Webhook Payload Adapters

## Objective

Enable headless and event-driven invocation of Katteb operations from workflow orchestration engines (such as Activepieces, Make, or autonomous agent runners) via standardized JSON stdin/stdout pipeline adapters.

## Tasks

<task type="auto">
  <name>Task 1: Implement Pipeline Event Adapter and Schema</name>
  <files>src/katteb/pipeline.py</files>
  <action>
    Create `src/katteb/pipeline.py` providing:
    - Pydantic schema `PipelineEventPayload` validating inbound webhook / automation requests:
      - `event`: Literal string, e.g. `"post_expansion_requested"`
      - `site`: WordPress site alias (e.g. `"destinations-ai"`, `"viatravelers"`)
      - `post_id`: Positive integer
      - `target_words`: Optional integer (500-5000, default 1500)
      - `enhancements`: Optional list of enhancement tokens (default `["tldr", "key_takeaways", "faq"]`)
      - `guidelines`: Optional custom guideline instructions
      - `brand_id` / `writing_style_id`: Optional style/brand identifiers
      - `dry_run`: Optional boolean (default False)
      - `receipt_dir`: Optional string destination for audit receipts
    - Function `process_pipeline_event(payload: dict | str, wp_manager: WordPressFleetManager | None = None) -> dict[str, Any]` which:
      1. Parses and validates input data using `PipelineEventPayload`.
      2. Validates site alias and connectivity.
      3. Invokes `wp_manager.expand_and_update_post()`.
      4. Generates an execution audit receipt if requested.
      5. Returns a structured JSON-serializable result dictionary with success status, post metadata, word counts, quality checklist, and errors if any.
  </action>
  <verify>
    Verify with Python interpreter or unit tests that `process_pipeline_event` validates schemas and handles both dict and raw JSON string payloads.
  </verify>
</task>

<task type="auto">
  <name>Task 2: Implement CLI Pipeline Dispatch Command</name>
  <files>src/katteb/cli.py</files>
  <action>
    Add `pipeline-dispatch` command to `src/katteb/cli.py`:
    - Flags:
      - `--stdin`: Read event payload directly from `sys.stdin` (standard for piped Activepieces / curl commands).
      - `--file` / `-f`: Path to JSON file containing event payload.
      - Inline overrides: `--site`, `--post-id`, `--words`, `--dry-run`.
    - Pure JSON output: When `--json` or `--stdin` is invoked, suppress console spinner and Rich table decorations, outputting pure JSON to `stdout` with exit code 0 on success or exit code 1 on failure.
  </action>
  <verify>
    Execute `katteb pipeline-dispatch --help` and test stdin piping with dry-run payload.
  </verify>
</task>
